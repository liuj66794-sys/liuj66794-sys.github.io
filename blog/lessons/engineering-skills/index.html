二、知识点之间的联系

主线五节课（第一至第五课）不是并列关系，而是 Matt 主流程 idea → ship 上前后相继的环节。 每一课的输出就是下一课的输入：

1

概览（第一课）：建立心理地图——主流程、三个入口（triage / diagnosing-bugs / wayfinder）、代码库健康类 skill。后面所有课都是这张地图的局部放大。

2

grill-with-docs（第二课）：用追问式访谈把模糊想法磨清楚，产出 CONTEXT.md、ADR 等文档。这是 spec 的原料。

3

to-spec（第三课）：把 grilling 的结果合成为一份 PRD/spec。spec 里声明的 seams（测试边界）直接决定下一课怎么切 ticket。

4

to-tickets（第四课）：把 spec 拆成 tracer-bullet 垂直切片，声明 blocking edges（阻塞边）。阻塞边决定 implement 的执行顺序。

5

implement（第五课）：按 frontier 逐个领取 ticket，内部用 /tdd 的 red → green 循环实现（测试只写在 spec 声明过的 seams 上），收尾跑 /code-review 双轴审查，最后提交。主流程到此闭环。

贯穿五课的三条概念线索：

  • context hygiene（上下文卫生）：第一课提出原则；第二到第四课的 grill → to-spec → to-tickets 要在同一个未中断的 context window 里完成，而第五课的每个 /implement 反过来要开全新 session——同一条原则的两面。
  • 垂直切片与 seam：第三课的 seams 定义切分边界，第四课的 tracer-bullet ticket 按它下刀，第五课的测试又只写在这些 seams 上——同一个思想在 spec、ticket、测试三个层面的体现。
  • issue tracker 作为单一事实源：spec 发布上去、ticket 带阻塞边发布上去、implement 从上面领取并关闭——工作流围绕它转。

三、推荐的复习顺序

1

先用速查表做全局回忆（2 分钟）：扫一遍场景索引，问自己“遇到 X 我会喊哪个 skill”。答不上来的行，标记为薄弱点。

2

按课序复习：第一课 → 第二课 → 第三课 → 第四课 → 第五课。主线顺序不能乱——每课都建立在前一课的输出上。第六课和第七课是入口场景，主线学完后随时可插进来复习。

3

每课内部的固定回路：看页顶目录回忆每节讲了什么 → 直接做“小测验”自测 → 只回读答错题目对应的章节 → 过一遍末尾术语表。

4

参考页不进复习主线：它们是工作中真正要调用某个 skill 时的查阅文档，用到再翻。

5

对照学习记录收尾：快速读一遍 learning-records/ 里对应的记录，确认自己当前的理解和当时确认的一致；不一致就回读课程。

四、如何进行复习（方法）

  • 主动回忆优先于重读：每课先看目录，合上正文，用自己的话讲出每一节的要点；讲不出的章节才点开细读。目录就是为此设计的。
  • 小测验当自测，不当练习：每课的测验题覆盖本课核心判断点。错题就是薄弱章节的路标，点目录直接跳过去。
  • 间隔重复：建议节奏——学完当天一次快速回忆（第 5–10 分钟）、3 天后一次完整回路、1 周后一次。每次都从速查表开始，而不是从第一课第一行开始。
  • 场景演练：随机想一个自己真实的工作场景（比如“有人报了个时好时坏的 bug”“老板丢来一个一句话需求”），先在脑子里选 skill，再翻速查表核对。
  • 实战检验：复习的终点是能在 AI 客户端里真的喊出来。挑一个低风险的真实任务，完整走一遍 grill → to-spec → to-tickets → implement。
