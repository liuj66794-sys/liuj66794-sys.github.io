一、不知道用哪个 skill 时

场景Skill一句话说明触发信号（用户原话）
完全不知道现在该调用哪个 skill /ask-matt skills 的路由器，描述你的处境，它会告诉你下一步该用什么。附 PHASE-BOUNDARIES.md 决策树：帮你判断处在哪个阶段边界。 “这么多 skill，我现在到底该用哪个？”
刚进入一个新项目，准备使用 Matt 的 engineering skills /setup-matt-pocock-skills 配置 issue tracker（问题追踪系统）、triage labels（分类标签）、CONTEXT.md / ADR 目录结构。首次使用前跑一次。 “我想在这个项目里用 Matt 的 skills，帮我配好环境。”

二、从想法到交付（Main Flow）

阶段Skill触发时机触发信号（用户原话）
1. 打磨想法（有代码库） /grill-with-docs 通过 relentless interview（追问式访谈）把想法磨清楚，同时维护 CONTEXT.md 和 ADR。 “我有个想法，帮我盘清楚。”
1a. 打磨想法（无代码库） /grill-me 没有 repo 时，纯对话版 grill，不保存任何本地文档。 “仓库还没建，先帮我把这个想法问清楚。”
（底层引擎） /grilling grill-with-docs / grill-me 内部调用的追问引擎；出现 "grill" 触发词时自动加载，一般不需要直接调用。现为 round-by-round 分轮采访：每轮问完整个 frontier，问题格式 ❓+编号+加粗标题+➡️推荐答案，同轮问题之间用水平线分隔（2026-08-20 起）。 “grill 我一下这个方案。”
2. 多 session 构建：生成 spec /to-spec 对话已经足够清楚，把它合成为一份 PRD/spec 并发布到 issue tracker。不再访谈，只做合成。 “聊得差不多了，把它整理成 spec 吧。”
3. 拆 ticket /to-tickets 把 spec 拆成 tracer-bullet（曳光弹）垂直切片，每个 ticket 声明 blocking edges（阻塞边）。 “把这个 spec 拆成可以分工做的 ticket。”
4. 实现 /implement 按 spec/ticket 实现，内部驱动 /tdd，最后跑 /code-review。 “照着这些 ticket 实现。”
（实现期底层规则） /tdd 测试驱动开发：red-green 循环、seams（测试边界）、anti-patterns。提到"先写测试"时自动加载。 “先写测试” / “用 TDD 来做。”
5. 代码审查 /code-review 针对某个 commit/branch/tag 做 Standards（规范） + Spec（需求）双轴审查，两个子 agent 并行。 “review 一下这个分支” / “review since X。”

三、入口与分流（On-ramps）

你遇到的情况Skill说明触发信号（用户原话）
有人报 bug / 提需求，需要先分类整理 /triage 把 issue/PR 推过一个状态机：分类 → 验证 → 必要时 grill → 输出 agent-ready brief（可直接交给 agent 的简报）。 “有人提了个 issue，帮我分类处理一下。”
有东西坏了，而且不是一眼能看出的 bug /diagnosing-bugs 先建 tight feedback loop（紧密反馈回路），再 reproduce → hypothesise → instrument → fix → post-mortem。 “这个 bug 我复现不了” / “帮我 debug 一下，它莫名其妙地慢。”
项目/功能太大，一个 session 装不下 /wayfinder 在 issue tracker 上画 shared map（共享地图），把调研拆成决策型 ticket，逐个解决直到路径清晰。 “这个项目太大了，我都不知道从哪下手。”

四、代码库健康

目标Skill说明触发信号（用户原话）
扫描架构问题，找出 deepening 机会 /improve-codebase-architecture 扫描代码库找出 deepening opportunities（深化机会），生成 HTML 报告，然后进入 grilling 循环。 “扫一下这个代码库有什么架构问题。”
设计/讨论模块接口的共享词汇 /codebase-design deep module（深模块）、interface（接口）、seam（测试边界）、adapter（适配器）、leverage（杠杆）、locality（局部性）。 “这个模块的接口该怎么设计？”
维护领域术语 / 写 ADR /domain-modeling 更新 CONTEXT.md（术语表），为难以逆转的架构决策记录 ADR。2026-08-13 起触发点明确覆盖“正在写 CONTEXT.md / ADR”这件事本身。 “我们在讨论术语怎么定” / “该更新 CONTEXT.md 了” / “这个决策值得记个 ADR。”

五、工程配置与测试工具

目标Skill说明触发信号（用户原话）
给仓库加 pre-commit 钩子 /setup-pre-commit 配置 Husky + lint-staged（Prettier）、type check、测试，提交时自动跑。 “给我配个 pre-commit，提交前自动格式化和跑测试。”
防止 AI 执行危险 git 操作 /git-guardrails-claude-code 给 Claude Code 配 hooks，在 git push、reset --hard、clean、branch -D 等命令执行前拦截。 “别让 AI 乱跑 git push / reset。”
测试里的 as 断言换成 shoehorn /migrate-to-shoehorn 把测试文件中的 as 类型断言迁移到 @total-typescript/shoehorn（部分测试数据）。 “把测试里的 as 断言都换成 shoehorn。”
搭建课程/练习题目录 /scaffold-exercises 创建带 sections、problems、solutions、explainers 的练习目录结构，并通过 lint。 “帮我搭一套练习题的目录结构。”
把手工配置流程做成交互式向导 /wizard 生成 bash 向导脚本，带人完成只有人能做的步骤：开通基础设施、配凭证/CI secrets、一次性迁移。按阶段数报进度，不给时间预估。 “把这套手工配置流程做成一个向导。”

六、跨 session、写作与辅助

场景Skill说明触发信号（用户原话）

七、实验性 skills（in-progress）

以下来自仓库的 skills/in-progress 目录，行为可能不稳定，调用前先读各自的 SKILL.md。

场景Skill说明触发信号（用户原话）
立刻交接给后台 agent 继续干 /claude-handoff 把当前对话交接给一个全新后台 agent，马上接手工作。 “马上交接给一个后台 agent 接着干。”
把工作流需求盘成 spec /loop-me 在当前工作区内，针对你想构建的 workflows 做 grill，产出 spec。 “帮我把要做的工作流盘成 spec。”
把 TS 仓库改造成 deep modules /setup-ts-deep-modules 接入 dependency-cruiser，让每个 package 的实现藏在子目录里，只经入口文件访问。 “把这个 TS 仓库改造成 deep modules 结构。”
把 spec + tickets 并行实现成一个 PR /implement-spec （2026-08-21 新增）把 spec 的 tickets 当任务图（含阻塞边），并行派发 implementer 子 agent 各自在 worktree 干活，合并成单个 PR，收尾跑 code-review。 “把这个 spec 和它的 tickets 实现掉。”
复盘一次编码会话 /retro （2026-08-24 新增）回顾指定会话（默认当前会话），从导航、自动检查、编码规范、AGENTS.md 瘦身、工具经济、空转指令、信息获取七个维度提出改进建议，按严重度排序。 “帮我给这次会话做个复盘。”
写作第 1 阶段：挖掘素材 /writing-fragments explore 阶段——从原始材料中挖 fragments（碎片），还没有结构。 “帮我把这些素材挖成碎片。”
写作第 2 阶段：按节奏组装 /writing-beats exploit 阶段——把素材组装成 beats（节奏点）的旅程，每个术语先落地再使用。 “把这些素材按节奏组装起来。”
写作第 3 阶段：成文 /writing-shape exploit 阶段——把材料逐段塑造成文章。 “把这些材料写成文章。”
