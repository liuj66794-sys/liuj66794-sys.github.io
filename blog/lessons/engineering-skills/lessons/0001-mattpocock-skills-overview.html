第一课：Mattpocock Skills 概览与调用方式

你已经把 39 个 Mattpocock Skills 安装到了本地。这一课只做一件事： 建立一张心理地图——知道这些 skill 是干什么的、怎么触发、以及遇到常见任务时该先抓哪一个。

主源推荐（Primary Source）

本课内容基于官方 skill 定义，建议精读原文： mattpocock/skills · 仓库 README 和 ask-matt/SKILL.md （本地 ~/.agents/skills/ask-matt/SKILL.md）。

1. Skill 是什么？

一个 skill 就是一份给 AI 的“工作说明书”：它定义了面对某类任务时，AI 应该遵循的流程、使用的词汇、输出的格式。

安装后，skill 会出现在多个 AI 客户端能识别的地方（Kimi Code CLI、Claude Code、Cursor、Codex 等）。 有些 skill 是 model-invoked（模型可自动调用）， 有些是 user-invoked（用户手动触发）。 作为学习者，你暂时只需要关心后者：看到合适的场景，喊出它的名字。

2. 主流程：idea → ship

Matt 把大部分工程工作抽象成一条主流程。记住这条线，你就记住了 half of the skills：

1

打磨想法：用 /grill-with-docs（有代码库）或 /grill-me（无代码库）进行 relentless interview（追问式访谈）。

2

生成 spec：想法清楚后，用 /to-spec 把它写成 PRD/spec，发布到 issue tracker（问题追踪系统）。

3

拆 ticket：用 /to-tickets 把 spec 拆成 tracer-bullet（曳光弹）垂直切片，标出 blocking edges（阻塞边/依赖关系）。

4

实现：用 /implement 逐个 ticket 实现，内部走 /tdd，最后跑 /code-review。

关键原则：context hygiene（上下文卫生）

步骤 1–3 尽量放在同一个未中断的 context window（上下文窗口）里完成，直到 /to-tickets 结束。 每个 /implement 再开新 context，从 ticket 出发，避免上下文污染。

3. 三个入口场景

不是每次工作都从“新想法”开始。Matt 还设计了三个入口 skill：

  • /triage —— 处理别人报来的 bug / 需求，整理成 agent-ready 的 issue。
  • /diagnosing-bugs —— 难 bug 的诊断流程，核心是“先建 tight feedback loop（紧密反馈回路），再假设”。
  • /wayfinder —— 项目太大、路径不清时，先在 issue tracker 上画 map，逐个解决决策。

4. 代码库健康

除了功能开发，还有一些 skill 用来保持代码库健康：

  • /code-review —— Standards（规范） + Spec（需求）双轴审查。
  • /improve-codebase-architecture —— 扫描 deepening opportunities（加深机会），生成 HTML 报告。
  • /codebase-design —— deep module（深模块）共享词汇。
  • /domain-modeling —— 维护 CONTEXT.md 和 ADR（架构决策记录）。

5. 怎么调用？

客户端调用方式
Kimi Code CLI /skill-name 或直接用 skill 名；触发词匹配时会自动加载。
Claude Code /skill-name
Cursor / Copilot / Cline 取决于客户端的 prompt/skill 机制；这些 skill 以 symlink/universal 形式存在。

6. 快速小测验

你有一个模糊的新功能想法，但还没想清楚细节，应该先调用哪个 skill？
/code-review 的双轴审查是哪两个轴？
当前对话已经积累了大量上下文，你需要换一个新 session 继续，应该用？
一个项目太大、路径不清晰，应该先启动哪个 skill 来规划？

7. 本课收获

  • Mattpocock Skills 是结构化的 AI 工作流，不是随机提示词。
  • 核心主线：grill → to-spec → to-tickets → implement（内部 tdd + code-review）。
  • 入口 skill：triage、diagnosing-bugs、wayfinder。
  • 代码库健康 skill：code-review、improve-codebase-architecture、codebase-design、domain-modeling。
  • 不确定时，先喊 /ask-matt。

8. 术语表

术语解释
model-invoked AI 模型可以根据上下文自动决定是否调用该 skill。
user-invoked 必须由用户手动输入 skill 名称才能触发。
slash command 以 / 开头的命令形式，用于触发 skill。
context window AI 一次能处理的文本总量。超出后早期内容会被压缩或遗忘。
tracer-bullet 曳光弹。一种贯穿所有层的垂直切片，用来快速验证完整路径是否可行。
blocking edges 阻塞边。表示一个 ticket 必须先完成哪些其他 ticket 才能开始。
relentless interview relent 追问式访谈。 agent 持续、细致地追问，直到把模糊想法磨清楚。
deep module 深模块。接口小、实现大的模块，调用方学习成本低、隐藏复杂度高。
shared understanding 共同理解。双方对范围、术语、关键决策达成一致的状态。
issue tracker 问题追踪系统。比如 GitHub Issues、Linear、Jira 等，用于管理 ticket。

9. 实战任务

光学不练等于没学。请打开你自己常用的一个 AI 客户端，用你手头的一个真实任务完成下面的练习：

  1. 选一个你现在手头真实存在的任务（新功能想法、bug、或整理 issue 都可以）。
  2. 对照 速查表，按本课主流程判断这个任务处在哪个阶段、该调用哪个 skill。
  3. 在你的 AI 客户端里实际调用一次这个 skill（比如 /grill-with-docs 或 /triage）。
  4. 观察它的实际行为：它是怎么追问/产出的？和你预期的一致吗？
  5. 用两三句话记录调用结果，包括你选它的理由和实际效果。
自检标准
  • 你能一句话说清楚这个任务处在主流程的哪个阶段。
  • 你能说出为什么选择这个 skill，而不是其他几个候选。
  • 你实际完成了一次调用，而不是只看了文档。
  • 你能判断这次调用的产出是否符合预期，并说出好在哪里或差在哪里。

完成后回来告诉我结果（贴出产出或描述过程），我会给你反馈。
