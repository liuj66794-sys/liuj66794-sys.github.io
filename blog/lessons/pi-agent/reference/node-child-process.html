Node.js 子进程（child_process）

程序里跑终端命令卡住时先查这里。回调式 API 统一用 promisify 转成 Promise 再 await。

核心用法

import { exec } from "node:child_process";
import { promisify } from "node:util";

const execAsync = promisify(exec);   // 回调式 → Promise 版

try {
  const { stdout, stderr } = await execAsync("node -v");
  console.log(stdout);
} catch (error: any) {
  // 退出码非 0 时 Promise rejected，错误对象带 code / stdout / stderr
  console.log(error.code, error.stderr);
}

命令结果三件套

名字是什么怎么拿
stdout命令的正常输出成功时解构 { stdout }
stderr命令的错误输出成功时解构 { stderr }；失败时在 error.stderr
退出码结束时报告的数字：0 = 成功，非 0 = 失败失败时在 error.code

run_command 工具骨架（Agent 设计：错误作为结果返回）

export const commandRunner: Tool = {
  name: "run_command",
  description: "运行一条终端命令，返回它的输出",
  execute: async (args) => {
    try {
      const { stdout, stderr } = await execAsync(args.command);
      return stdout.trim() || stderr.trim() || "（命令成功，没有输出）";
    } catch (error: any) {
      return `错误：命令失败，退出码 ${error.code}\n${error.stderr}`;
    }
  }
};

exec vs spawn（面试常考）

execspawn
输出方式全部攒到最后一次性给流式，边跑边给
适合场景短命令：node -v、git diff长命令：npm install、跑测试套件

常见现象速查

现象 / 报错原因与对策
'xxx' 不是内部或外部命令（Windows）命令不存在或拼错——退出码 1，报错在 stderr；先自己在终端敲一遍验证
成功但拿到 [object Object]忘了解构 { stdout, stderr }，把整个结果对象直接拼了字符串
打印出 Promise { <pending> }忘了写 await——拿到的是小票不是命令结果
ls 在 Windows 上失败exec 在 Windows 走 cmd.exe，没有 ls——用 dir，或选跨平台命令
一句话记住 promisify(exec) 转 Promise → await 取 { stdout, stderr } → 退出码非 0 走 catch，读 error.code 和 error.stderr。工具失败不抛错，把退出码 + 错误输出作为结果返回。
