第 3 课 · 模块与 npm 脚本

约 1962 字大约 7 分钟

2026-09-01

阶段 0 · 模块 A（TypeScript 起步）· 第 3 课 ｜ 预计 40 分钟 ｜ 前置：第 2 课

这是本课阅读版。打开互动课程（在新窗口打开），即可在同一页阅读与练习。

这节课结束时，你会把上一课的 tools.ts 拆成三个文件，用 import/export 组织，并通过 npm run start 运行整个项目。同时你还会搞懂一个上一课留下的关键问题：为什么 tsx 不报错，但 TypeScript 其实会报错？

为什么学这个 · Mission 关联

你看 pi-mono 仓库时，会发现它不是一个巨大文件，而是按职责拆成 packages/ai、packages/agent、packages/coding-agent 等包。你即将写的 PatchPilot 也会拆成 agent/、tools/、context/ 等目录。模块化和 npm 脚本就是组织这些文件的基础。

温故：先回忆，再学新内容

1.（第 2 课）用一句话说：Record<string, Tool> 描述的是什么？

显示答案

"键为字符串、值为 Tool 的对象"——它描述的是注册表这个容器的形状，不是"获取所有工具"这个动作。

2.（第 1 课）npm init -y 做了什么？生成的文件叫什么？

显示答案

在当前目录生成 package.json——项目的"身份证"，记录依赖清单与可运行脚本。

3.（第 1 课）tsx 运行一个 TS 文件时做了哪两件事？（今天会看到它没做的第三件事）

显示答案

转译（把 TS 翻译成 JS）+ 运行。它没做的第三件事是类型检查——这正是本课第 5 节的主角 tsc --noEmit 的工作。

1. 为什么要把代码拆成多个文件

想象你搬到一个新城市，所有东西——衣服、厨具、书本、自行车——全部塞进一个巨型行李箱。每次找东西都要翻半天，这就是"所有代码写在一个文件里"的感觉。

模块化就是把代码按职责放进不同"房间"：

  • tool-types.ts：只放 Tool 接口定义
  • tools.ts：只放具体工具（calculator、greeter）
  • main.ts：程序的入口，负责组装和运行

这样你找东西更快，改东西也不容易影响 unrelated 的部分。

2. import / export：模块之间的门

一个文件要"暴露"什么给别人用，就用 export：

<code>// tool-types.ts
export interface Tool {
  name: string;
  description: string;
  execute: (args: Record<string, any>) => string;
}</code>

另一个文件想用它，就用 import：

<code>// tools.ts
import { Tool } from "./tool-types";

export const calculator: Tool = {
  name: "calculator",
  description: "计算两个数的和",
  execute: (args) => `结果是 ${Number(args.a) + Number(args.b)}`
};

export const greeter: Tool = {
  name: "greeter",
  description: "向指定的人问好",
  execute: (args) => `你好，${args.name}！`
};</code>

注意 ./tool-types 前面的 ./ 表示"当前目录下的文件"。如果省略 ./，Node 会以为你要找 npm 包。

3. 程序入口 main.ts

<code>// main.ts
import { Tool } from "./tool-types";
import { calculator, greeter } from "./tools";

const toolRegistry: Record<string, Tool> = {
  calculator,
  greeter,
};

function runTool(name: string, args: Record<string, any>): string {
  const tool = toolRegistry[name];
  if (!tool) return `错误：找不到名为 "${name}" 的工具`;
  return tool.execute(args);
}

console.log(runTool("calculator", { a: 10, b: 20 }));
console.log(runTool("greeter", { name: "L1U.J" }));</code>

4. npm 脚本：给常用命令起个名字

每次输入 npx tsx main.ts 很麻烦。我们可以在 package.json 里给常用命令起别名：

<code>{
  "name": "ts-playground",
  "version": "1.0.0",
  "scripts": {
    "start": "tsx main.ts"
  }
}</code>

然后运行：

<code>npm run start</code>

npm run 会到 package.json 的 scripts 里找对应的命令并执行。这是真实项目的标准启动方式。

5. tsx 不报错，但 TypeScript 会报错

上节课你故意把 runTool("calculator", 10) 传进去，结果程序跑出了 结果是 NaN，而不是类型错误。这是因为：

  • npx tsx 负责转译 + 运行：它把你的 TS 代码翻译成 JS，然后执行。它默认不检查类型。
  • npx tsc --noEmit 负责类型检查：tsc 是 TypeScript 官方编译器，--noEmit 表示"只检查，不生成 JS 文件"。

在 ts-playground 目录下新建一个 tsconfig.json 文件，内容如下：

<code>{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "target": "ES2022",
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "skipLibCheck": true
  }
}</code>

然后执行：

<code>npx tsc --noEmit</code>

如果代码里有类型错误（比如 runTool("calculator", 10)），就会看到红色报错。把错误改回去后再次运行，应该没有任何输出——没有输出就是"全部通过"。

动手任务（验收清单）

  1. 在 ts-playground 里把上一课的 tools.ts 拆成三个文件：
  • tool-types.ts：只放 interface Tool
  • tools.ts：只放 calculator 和 greeter 两个工具
  • main.ts：放注册表和 runTool 调度逻辑
  1. 确保三个文件之间用 import/export 正确连接。
  2. 修改 package.json，添加 "start": "tsx main.ts" 脚本。
  3. 运行 npm run start，看到两条正常输出。
  4. 新建 tsconfig.json（内容见上文），然后运行 npx tsc --noEmit，确认没有报错。
  5. 类型检查实验：在 main.ts 里临时加一行 runTool("calculator", 10)，运行 npx tsc --noEmit，把报错贴出来；然后删除这行，再次运行 npx tsc --noEmit 确认通过。

贴回给我：① npm run start 的输出；② npx tsc --noEmit 在故意写错参数时的报错信息；③ 用一句话解释 export 和 import 的关系。

小测

1. 一个文件想让别的文件用自己的接口，应该写什么？

  • A. 用 import 引入它
  • B. 用 return 返回它
  • C. 用 console 打印它
  • D. 用 export 暴露它
点开核对答案

答案：D（用 export 暴露它） —— export 用于从文件向外暴露内容，import 用于从其他文件引入内容。

2. 想看到 TypeScript 类型错误，应该运行哪个命令？

  • A. npx tsx main.ts
  • B. npm run start
  • C. npx tsc --noEmit
  • D. node main.ts
点开核对答案

答案：C（npx tsc --noEmit） —— tsx 默认只转译运行，不检查类型；tsc --noEmit 才是专门做类型检查的命令。

3. 导入当前目录下的 tool-types.ts，正确的写法是？

  • A. import from "./tool-types"
  • B. import from "tool-types"
  • C. import from "/tool-types"
  • D. import from "../tool-types"
点开核对答案

答案：A（import from "./tool-types"） —— ./ 表示当前目录下的本地文件；省略 ./ 会被当成 npm 包名。

4. package.json 里的 scripts 字段主要作用是什么？

  • A. 记录项目作者信息
  • B. 给常用命令起别名
  • C. 声明运行时许可证
  • D. 列出项目所有文件
点开核对答案

答案：B（给常用命令起别名） —— package.json 的 scripts 用于给常用命令起别名，npm run 执行它。

回忆挑战（遮住上文，先默写再对照）

1. 默写"只做类型检查、不运行代码"的命令；再说一遍 tsx 和 tsc 的分工。

显示答案

npx tsc --noEmit。tsx 负责转译 + 运行（不查类型），tsc --noEmit 负责只检查类型（不产生输出、不运行）。

2. 默写：把 Tool 从 tool-types.ts 暴露出来、并在 tools.ts 中引入它的两行语法。

显示答案
<code>export interface Tool { /* ... */ }        // tool-types.ts
import { Tool } from "./tool-types";       // tools.ts</code>

面试怎么考

面试中如果让你"介绍一下项目结构"，模块化思路就是得分点："我把工具定义、具体工具实现、入口逻辑拆到不同文件，用 ESM import/export 组织，并用 npm scripts 管理启动命令。"这节课让你能说出这样的话。
